# Mobile shell (Capacitor)

PitchSwipe's mobile apps are a **thin native shell** (Capacitor 8) around the
existing responsive Next.js web app. The shell contains no copy of the app: its
WebView loads the **deployed HTTPS URL** at runtime (`server.url`). The Next.js
app uses API routes and server rendering, so it cannot be exported as static
HTML and bundled into the app. Consequences:

- A deployed, reachable HTTPS PitchSwipe is required. The shell is useless without it.
- Web deploys update the app instantly; the native binary only changes for shell changes.
- `mobile/www/index.html` is a tiny bundled fallback ("Connecting..." then an offline
  Retry screen) so the WebView never starts blank. It is shown only if the remote URL
  cannot be loaded or none was configured when you ran `cap sync`.

The product spec (`docs/spec/01-product.md`) targets one responsive PWA. This shell is an
additional, optional distribution channel.

**Status: the native projects were generated and `cap sync` succeeds. Nothing in this
repo has been verified on a physical device, emulator or simulator.**

## Layout

| Path | Purpose |
| --- | --- |
| `capacitor.config.ts` | appId, name, `server.url` from env, navigation allow-list |
| `mobile/www/` | webDir; offline/connecting fallback page |
| `mobile/android/` | Android Studio project (sources committed, build output ignored) |
| `mobile/ios/` | Xcode project using Swift Package Manager (no CocoaPods needed) |

`mobile/android/app/src/main/assets/capacitor.config.json` and `mobile/ios/App/App/capacitor.config.json`
are generated by `cap sync` and are git-ignored, so **run sync before every build**.

## Prerequisites

- Node >= 20.19 and `npm ci`.
- Android: Android Studio, an Android SDK (compileSdk 36) and a JDK 17 or 21 (Android
  Studio's bundled JBR works; very new JDKs may not be supported by the Gradle plugin).
- iOS: a Mac with Xcode (the iOS project cannot be built or opened on Windows/Linux).
- A deployed HTTPS URL of the web app.

## Configuration (environment variables read by `capacitor.config.ts`)

| Variable | Meaning |
| --- | --- |
| `CAP_SERVER_URL` | URL of the deployed app, e.g. `https://pitchswipe.example.com`. Must be `https://`. |
| `CAP_DEV=1` | Dev profile: allows cleartext `http://` and sets `cleartext: true`. Never use for release. |
| `CAP_APP_ID` | Overrides the bundle/application id (default placeholder `app.pitchswipe.mobile`). |

The URL is baked into the generated native config at sync time, so re-run sync after
changing it. The config throws on an invalid URL, or on `http://` without `CAP_DEV=1`.

PowerShell:

```powershell
$env:CAP_SERVER_URL = "https://your-deployed-host"
npm run cap:sync
```

bash/zsh: `CAP_SERVER_URL=https://your-deployed-host npm run cap:sync`

### Dev profile (Android emulator against local `next dev`)

```powershell
npm run dev    # Next on :3000
$env:CAP_DEV = "1"; $env:CAP_SERVER_URL = "http://10.0.2.2:3000"
npm run cap:sync
```

`10.0.2.2` is the emulator's alias for the host machine. Microphone capture and Firebase
Auth on a non-HTTPS origin may behave differently than in production.

A real phone on the same Wi-Fi uses this machine's LAN address instead (for example
`http://192.168.0.10:3000`). `next dev` blocks its dev resources for hosts other than localhost, so
add that address to `.env.local` and restart `npm run dev`:

```
NEXT_DEV_ALLOWED_ORIGINS=192.168.0.10
```

The firewall must allow incoming connections to Node on port 3000 on a private network. A dev APK
only works while this machine runs `next dev` on that address.

## Build and run

Android (debug APK):

```powershell
$env:CAP_SERVER_URL = "https://your-deployed-host"
npm run cap:sync
cd mobile/android
.\gradlew.bat assembleDebug    # ./gradlew assembleDebug on macOS/Linux
# APK: mobile/android/app/build/outputs/apk/debug/app-debug.apk
```

Or `npm run cap:android` to open the project in Android Studio and press Run. Gradle needs
an SDK location: set `ANDROID_HOME`, or let Android Studio create `mobile/android/local.properties`
(git-ignored; never commit it).

iOS (on a Mac):

```bash
npm ci
CAP_SERVER_URL=https://your-deployed-host npm run cap:sync
npm run cap:ios    # opens mobile/ios/App/App.xcodeproj in Xcode
```

In Xcode choose your Team under Signing & Capabilities, pick a simulator or device and Run.
`npm run cap:doctor` reports the environment status.

## Changing the app id, name, icons, splash

- **appId**: set `CAP_APP_ID` or edit `capacitor.config.ts`, then update
  `applicationId`/`namespace` in `mobile/android/app/build.gradle` (and the `MainActivity`
  package if you add custom code) and `PRODUCT_BUNDLE_IDENTIFIER` in the Xcode project.
  `cap sync` does not rename these for you. Choose the final id before the first store
  upload; it cannot change afterwards.
- **Name**: `appName` in `capacitor.config.ts`, plus `mobile/android/app/src/main/res/values/strings.xml`
  and the iOS `CFBundleDisplayName`.
- **Icons/splash (Android)**: generated from the PWA icons in `public/icons`. Launcher icons:
  `icon-512.png` (legacy square), a circle crop of `icon-maskable-512.png` (round), and the
  maskable icon as the adaptive foreground on `#16803C`. Splash: the icon centred on white
  (`splash.png` before Android 12; from 12 on the system splash shows the adaptive icon on white,
  see `AppTheme.NoActionBarLaunch`). The marks are placeholders until the final logo exists;
  regenerate all of them together when it does. iOS still has Capacitor's defaults.

## Permissions

- Android: `INTERNET`, `RECORD_AUDIO` (voice notes), and a `<queries>` entry for the
  `android.speech.RecognitionService` intent. From Android 11 the app cannot see the phone's speech
  service without it, and voice notes would stay off. Android asks for the microphone the first time
  the swiper taps "Or say it out loud".
- iOS: `NSMicrophoneUsageDescription` and `NSSpeechRecognitionUsageDescription` (both needed by the
  speech plugin). They are in `Info.plist` already, ready for when the plugin can be linked (see below).
- No camera, location or other permissions are declared because the app does not use them.

## Voice notes in the apps

The WebViews have no speech recognizer (Web Speech API), so inside the app voice notes use the
phone's own speech service through `@capacitor-community/speech-recognition` 7.0.1 (Google's
recognizer on most Android phones, Apple's on iOS).

- The app loads the live site, so the plugin has to be **in the installed app** (added by `cap sync`)
  and the web code calls it through the Capacitor bridge (`window.Capacitor.Plugins.SpeechRecognition`,
  read at call time in `src/features/claims/native-dictation.ts`). A new app build is needed before users get it.
- Rollout order: deploy the web code first. It is safe for app builds without the plugin, which show the
  message below. Then ship the new app build.
- The web code picks the engine: in the app, if this build has the plugin and `available()` says yes,
  the phone listens; the browser path is never used in the app. An app build without the plugin says
  "Voice notes are not in this version of the app. Type your comment instead."; a phone with no
  speech service says so too.
- Same flow as the website: pick a language, live words, a 30 s cap that starts when listening starts,
  Stop and keep, Delete, then review and the English translation. **No audio is kept in the app**
  (the recognizer holds the microphone, so nothing is recorded) and the "Let the founder play my voice
  note" tick is not shown. There is no level meter in the app.
- Android's recognizer stops by itself after a pause. That counts as "Stop and keep", as it does in
  Chrome; the swiper can start another voice note to say more.
- **iOS is not wired up yet.** The plugin ships no `Package.swift` and this iOS project uses Swift
  Package Manager, so `cap sync` skips it ("does not have a Package.swift") and `CapApp-SPM/Package.swift`
  does not list it. The iOS app therefore says voice notes are not in this version of the app. To add it:
  wait for an upstream release with SPM support (the "support capacitor 8" issue is open), or write a
  small Swift plugin in the app named `SpeechRecognition` with the same methods and events (`available`,
  `checkPermissions`, `requestPermissions`, `start`, `stop`, `isListening`, `getSupportedLanguages`,
  `partialResults`, `listeningState`), and build it on a Mac. The web code needs no change for either.

### Device test checklist (a real Android phone)

The voice engine is in the web code, and the app loads it from `CAP_SERVER_URL`. So first, either deploy
this branch's web code to the site the app loads, or point the app at a dev server running it (see
[Dev profile](#dev-profile-android-emulator-against-local-next-dev)). Otherwise the app runs the old web code
and says "Voice notes are not in the app yet", which looks like a plugin failure but is not. Then run
`CAP_SERVER_URL=... npm run cap:sync` (it also writes the git-ignored `capacitor.plugins.json` that registers
the plugin, so a fresh checkout needs it) and `./gradlew assembleDebug` (see [Build and run](#build-and-run)).
Install that build and, signed in with a verified email:

- [ ] Tap "Or say it out loud": Android asks for the microphone once. Deny it: the app says the microphone or
      speech recognition is blocked and to allow it in the phone's settings. Allow it in Settings and try again.
- [ ] English: words appear while you speak; the clock starts at 0:00 when listening starts; "Stop and keep"
      keeps the last words; the review shows the words and says your voice is not kept (no "play" tick).
- [ ] Hindi (and one more Indian language, e.g. Tamil): the words come back in that script, and the English
      translation appears.
- [ ] Pause for a few seconds mid-sentence: the note ends and is kept (no lost words, no hang on "Finishing...").
- [ ] Say nothing: within a few seconds the app says "We did not hear anything".
- [ ] Talk for more than 30 s: it stops by itself at 0:30 and keeps the words.
- [ ] Delete while listening: nothing is kept, and the microphone indicator in the status bar goes off.
- [ ] Airplane mode: either the words still come (on-device recognition) or the app shows a plain message;
      no crash and no endless "Listening".
- [ ] A phone without Google's speech service (or with it disabled): the app says the phone has no speech
      recognition service.
- [ ] An app build from before this change: it still says voice notes are not in this version of the app.

## Navigation and sign-in

`allowNavigation` contains only the host of `CAP_SERVER_URL` (always allowed anyway).
Email/password Firebase sign-in uses `fetch`/XHR to Google's identity endpoints, which is
not WebView navigation, so no Firebase domains are listed.

## Deep links for `/d/[slug]` (TODO)

Opening shared deck links (`https://<domain>/d/<slug>`) in the app needs the final production domain:

1. Android App Links: add an `<intent-filter android:autoVerify="true">` with
   `<data android:scheme="https" android:host="<domain>" android:pathPrefix="/d/"/>` to
   `MainActivity`, and host `/.well-known/assetlinks.json` with the release signing
   certificate SHA-256 fingerprint.
2. iOS Universal Links: enable the Associated Domains capability (`applinks:<domain>`) and
   host `/.well-known/apple-app-site-association` (no extension, `application/json`) with the
   Team ID, bundle id and the `/d/*` path.
3. Optionally handle `appUrlOpen` via `@capacitor/app` (not installed).

## Store release checklist

- [ ] Final appId, name, version code / build number, icons and splash.
- [ ] Production `CAP_SERVER_URL` over HTTPS, `CAP_DEV` unset, then `cap sync`.
- [ ] Android: generate an upload keystore (keep it and passwords out of git), build a signed
      AAB (`./gradlew bundleRelease`), enrol in Play App Signing.
- [ ] iOS: Apple Developer account, App Store Connect record, signing, archive and upload.
- [ ] Privacy: the app collects **email addresses** (account). In the Android app, voice notes collect the
      transcript text and its English translation (no audio; the phone's speech service, usually Google's,
      turns speech into text). Complete Google Play Data safety and Apple App Privacy labels
      accordingly, and provide a privacy policy URL and an account deletion path (both
      stores require one for apps with accounts).
- [ ] Test on real devices: sign-in, offline fallback, and the voice-note checklist above (on iOS,
      until the plugin is linked, the comment sheet says "Voice notes are not in this version of the app").

## Known limits

- No push notifications.
- Native plugins: `@capacitor/haptics` (swipe, answer and reward feedback; the web code reads it
  from `window.Capacitor` and falls back to `navigator.vibrate`) and
  `@capacitor-community/speech-recognition` (voice notes, Android only for now; see above). Capacitor 8's built-in SystemBars
  draws the app edge to edge with dark status-bar icons and passes the insets to CSS as
  `--safe-area-inset-*` (used through `--safe-top` / `--safe-bottom` in `globals.css`).
- Needs network: offline shows only the fallback page.
- Firebase popup/redirect sign-in (for example Google) does not work in a WebView, so only
  email/password is supported.
- **Apple guideline 4.2 (minimum functionality)**: App Review may reject a pure web
  wrapper. If shipping to iOS, add real native value, for example: native share sheet for
  deck links, haptics on swipes, push notifications for new swipes, native audio recording,
  Sign in with Apple (required if you add other third-party logins) and deep links.
- A remote-URL shell depends on the live site: an outage or broken deploy breaks the app.
